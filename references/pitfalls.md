## 投递与维护反例（当前有效 v5.6.1，2026-10-12 建立）

| 触发条件 | 错误表现 | 正确处理 |
|---|---|---|
| 打开默认推荐标签 | 岗位池偏离目标 | 点击配置的频道标签（channel_tab）并核对选中标签；URL 不足以判断频道 |
| 从历史 surface_cache.json 取岗位 | 当前 DOM 无 jobId，出现 no_link_match | 只操作本轮当前页面抓取的岗位 |
| 用户切换页面或刷新 | 卡片消失、目标错位 | 停止当前岗位，重新抓取并读取 JD |
| JD 读取失败仍 APPROVE | 无依据投递或使用旧 JD | 写入 READ_FAILED，阻断决定和投递 |
| 自动打招呼明确关闭 | 点击沟通却没有有效首条消息 | 记录 blocked；无设置证据时不能猜测关闭 |
| 只看到 popup=sent | 点击发送被误当成送达 | 以 `chat_list_match`（会话列表：目标公司+送达/您好）或 `stay_btn` 为权威信号；孤立的 popup=sent 不算成功 |
| 点击留在此页（路径B） | 仅看弹窗就当成功 | 须捕获 `stay_btn` 证据方为成功信号；未记录 `stay_btn` 仍不能判定（v5.6.1 新增） |
| 全页出现您好或公司名 | 其他聊天或岗位列表造成误匹配 | 限定目标聊天对象和消息区域核验 |
| 重复追加失败记录 | 失败数量膨胀 | 按 jobId 去重，成功优先，保留状态变更审计 |
| 把 unknown 归入明确失败 | 统计误导用户 | blocked、fail、unknown 分别统计，兼容历史 reason 前缀 |
| 用处理岗位计算成功数 | 成功数虚高 | 只统计最终 success 的唯一 jobId |
| 空行业或失败行业算覆盖 | 覆盖行业虚高 | 只统计成功岗位非空行业，空行业单列 |
| PowerShell 默认管道写中文 | 文件实际变成连续问号，原字无法恢复 | 通过 UTF-8 文件写入，回读核对中文原文；不得用编译成功代替内容验收 |
| 仅检索字段便宣布升级完成 | 字段存在但行为未实现 | 逐项验证代码路径、状态转换、统计结果和真实运行证据 |

历史数值需谨慎解释：此前报告把空行业分组计为一个行业，因此显示 3；现有数据中非空成功行业为 2，空行业岗位为 1。旧失败列表含重复和 reason 为 unknown 的记录，不能把整个列表长度解释为明确失败数。准确迁移数量须以迁移前备份验证，不能凭记忆补写。
